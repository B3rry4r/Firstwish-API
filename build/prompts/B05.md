Cases (input -> expected), beyond P5-COMMON's per-endpoint tests:
 1. Start: the body names what is bought (never an amount: 422 if one is sent); the server prices it with price.quote, stores a
    Payment (pending, amountKobo, price-book version, reference issued by the server) and asks the payments port to initialise;
    answers PaymentStarted {payment:{reference,state,amountKobo,authorizationUrl}, item}. The same Idempotency-Key twice returns the
    same payment and makes one row; a different body under the same key is 409.
 2. Webhook: only a valid HMAC-SHA512 signature over the RAW body is accepted (wrong, missing, or valid over a different body: 401);
    the event is stored once by (provider, eventId); a replay answers 200 and changes nothing; an event for an unknown reference is
    stored and flagged, not dropped; success with an amount or currency that differs from the payment's is NOT fulfilled and is flagged for staff.
 3. Paid: in ONE transaction, with the payment row locked: state paid, ledger entries written (double entry: every transaction's
    entries sum to zero; test the sum over a random run of payments), fulfilledAt set once, the registered handler for the line called
    exactly once. Webhook and verify arriving at the same moment for one payment fulfil once (run them in parallel in a test).
 4. A handler that throws rolls the whole thing back (payment stays pending, no ledger row), and the next delivery retries cleanly.
 5. Verify endpoint (the page comes back from Paystack): asks the port; same path as the webhook; never trusts a query parameter.
 6. Abandoned: a pending payment past the declared time is marked abandoned by a job handler (register it with the jobs frame if B06
    has merged it, else export the function and say so); a late success after abandon still fulfils once and is flagged.
 7. List and detail are the payer's own (owner check in the query); nothing about a payment is public (A5). The ledger is never
    updated or deleted (the database refuses; do not try): a correction is a new pair of entries.
