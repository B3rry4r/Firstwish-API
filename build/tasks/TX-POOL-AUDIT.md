# TX-POOL-AUDIT (read-only, text only; head 7d17760 of claude/sleepy-mayer-f0hkb8)

## Coverage
- Call sites read: 166 `$transaction(` in 66 non-test files under src (all of them; 100 more sit in specs and were left). 3 take a named callback (`$transaction(run)` events.service.ts:137, two multi-line stored-files calls) and were read too.
- Method: a brace-matched pass over every callback body (166), then every method in src that is given a `tx`/`db`/`Tx` (the "two levels deep" helpers), then the fulfilment handlers (they get `c.tx`), the two registered hooks (`registerEnd`: PassCover.applyEnd; `registerSealAccrual`: accrueAtSeal) and the start checks (`onStart`: purchases, wish-keeps, concierge). Four scans: (1) any `this.prisma|db|client` or bare `prisma|db` token inside a callback; (2) any `this.x.y(` call with no `tx` argument inside a callback or a tx-taking helper; (3) calls to the 28 methods that default their client to the pool (`db = this.prisma`: jobs.schedule/cancel/retryParked, suppression.has/add, entitlements.row, book.versionAt/latestPublished/load/quote, roleAccess.all/opens, payout threshold/runDay, restoreDays, creator rules, support extras/detail, file-jobs scheduleCleanup/removeAccountFiles, assertStartable) that omit the client; (4) a nested `$transaction` inside a callback. Then each hit was read by hand.
- Not run (rules): no server, jest or database. Findings are from reading; the one finding below is not reproduced.
- Limit: a call that reaches the pool through a function stored in a variable, or a dynamic call, would not match the scans. Free functions given `this.prisma` from inside a callback: none found.
